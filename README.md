# CardioVision 3D

**See the signals. Explore the anatomy. Understand the risk.**

CardioVision 3D is a full-stack educational/research prototype for four independent tabular model outputs (overall CAD, LAD, LCX and RCA), target-specific feature explanations, model evaluation and an interactive procedural coronary heart scene. It is **not a diagnostic product**. No dataset or trained production model artifacts are bundled in this repository; the interface reports the resulting setup state rather than inventing a schema, demo record, prediction or metric.

> **EDUCATIONAL / DECISION-SUPPORT PROTOTYPE — Predictions are generated by machine-learning models and are not a diagnosis. They must not replace professional clinical assessment, ECG or imaging interpretation, coronary angiography, or other appropriate medical evaluation. These outputs are not validated for clinical decision-making.**

## Current data and model status

The checkout did not contain a clinical dataset. Therefore no real training run or held-out evaluation has executed; no clinical accuracy, ROC-AUC, patient count or model readiness claim is made. The API starts in a degraded/setup-required state. After dataset audit, the schema-driven form and synthetic demo become available; real inference requires all four trained model artifacts.

## Requirements

- Python 3.11+
- Node.js 20+
- A local CSV/XLSX containing the inspected clinical feature fields plus documented overall CAD/Cath and LAD, LCX, RCA targets for four-model training.
- UCI Z-Alizadeh Sani source provenance and CC BY 4.0 attribution; extensions may have separate license/consent terms. See [`data/README.md`](data/README.md).

The base UCI file may not provide every vessel-specific target. Do not derive vessel labels from clinical measurements; use a documented extension or stop with a clear label-definition error.

## Install and run

### Backend

```bash
cd backend
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # Optional; export variables in your shell or configure your host

# From the repository root, once the dataset is placed under data/:
.venv/bin/python -m training.audit_dataset --data ../data/z_alizadeh_sani_extension.csv
.venv/bin/python -m training.train_models --data ../data/z_alizadeh_sani_extension.csv

# Start the API (run from backend/):
.venv/bin/uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

The audit command generates `backend/artifacts/schema.json`. It enables the real dataset-derived form and synthetic feature-wise profile, but **not inference**. Training writes four joblib pipelines plus schema, metadata, metrics and leakage audit JSON. Restart the API after generating or replacing artifacts. Check every positive-class definition against the source data dictionary. Numeric encodings such as 0/1 always require an explicit positive-label flag; semantic text labels may be inferred only when unambiguous. Example:

```bash
.venv/bin/python -m training.train_models \
  --data ../data/z_alizadeh_sani_extension.csv \
  --cad-target Cath --cad-positive-label CAD \
  --lad-positive-label 1 --lcx-positive-label 1 --rca-positive-label 1
```

Target names default to CAD when present, otherwise Cath; vessel names default to LAD, LCX and RCA. The trainer refuses an ambiguous target mapping. It prints the leakage audit and does not claim real inference if a pipeline is missing.

### Frontend

```bash
cd frontend
npm install
cp .env.example .env.local       # Optional; default uses the same-origin Next proxy
npm run dev
```

Open the URL reported by Next. The dev server proxies browser requests from `/backend/*` to `BACKEND_URL` (default `http://127.0.0.1:8000` on the server side). Browser code uses a relative URL and never calls localhost directly. Set `BACKEND_URL` to the deployed FastAPI HTTPS origin for Vercel/other hosting. `NEXT_PUBLIC_API_BASE_URL` is optional for direct API access and requires explicit backend CORS allowlisting.

### API routes

- `GET /health` — service, model and missing-artifact readiness.
- `GET /api/schema` — columns from a local dataset audit; no guessed schema.
- `GET /api/model-metrics` — actual saved evaluation JSON or an explicit pending state.
- `GET /api/demo-patient` — a clearly synthetic, schema-compatible per-feature median/mode profile; it carries no labels.
- `POST /api/predict` — validates feature fields and invokes all four fitted pipelines.
- `POST /api/explain` — target-specific local single-feature perturbation explanation and saved global importance.

Interactive API docs are available at `/docs` while the backend runs.

## Tests and checks

```bash
# Backend (from backend/)

# Frontend (from frontend/)
npm test
npm run lint

```

Training tests use isolated synthetic fixtures only. They exercise saved pipeline load and inference, but do not create application artifacts and are not model-performance results.

## Deployment

Deploy `frontend/` as a Next.js app (for example Vercel) and `backend/` on a Python 3.11 host using `backend/Dockerfile` or Uvicorn. Set `BACKEND_URL` on the Next host; set `CARDIOVISION_ARTIFACT_DIR` to the mounted artifact directory on the backend; configure `CORS_ORIGINS` only if using direct browser-to-API requests. Keep datasets and joblib artifacts out of Git. See [`docs/architecture.md`](docs/architecture.md) and [`docs/data-and-ml-methodology.md`](docs/data-and-ml-methodology.md).

## Demo and limitations

The 3D heart and coronary paths are a stylized procedural illustration and are not patient-specific anatomy. Vessel colors represent uncalibrated model-score bands only; artery geometry does not narrow with the score. Feature attribution is approximate and non-causal. Read [`docs/demo-script.md`](docs/demo-script.md) for a 7–8 minute recording plan; no video has been recorded or uploaded.
